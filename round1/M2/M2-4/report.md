## 3. 检测前端

### 3.1 置信度阈值：扫描出来的 0.5（`results/conf_sweep.csv`）

| conf | 检测数 | 分配 ID 数 | 空帧 | 最大同时航迹 |
|---|---|---|---|---|
| 0.15 | 5732 | 33 | 24 | 4 |
| 0.25 | 5455 | 28 | 39 | 4 |
| 0.30 | 5374 | 24 | 39 | 4 |
| 0.40 | 5246 | 18 | 39 | 4 |
| **0.50** | **5097** | **15** | 66 | 3 |
| 0.60 | 4740 | 25 | 245 | 3 |

0.15 时背景低分假阳性变成幽灵航迹（33 条 ID，画面上只有 3~4 个物体）；0.6 时真目标开始漏检，
断档变长、空帧从 66 涨到 245，ID 反而回到 25。取 **0.5**。

### 3.2 两个必须修的上游问题

1. **NMS 太松会造出"双胞胎"**：ultralytics 预测默认 `iou=0.7`，同一个杯子被 0.60（松框）与
   0.97（紧框）各框一次、IoU 0.55，两条都活下来 → 追踪层给一个物体开两条 ID。现在
   `detector_adapter.py --iou 0.45`。
2. **类别抖动会造出"双胞胎"**：手机被检成 tissue 时新生一条航迹，下一帧变回 phone 又新生一条，
   两个框叠在一起、ID 却是两条。修法是**两级匹配**：先同类匈牙利；只剩孤立检测时，才允许与
   **正在预测态**的航迹跨类配对（并把航迹类别更正）。这样不会像"一次性跨类匹配"那样抢走别的
   目标的检测（实测那版会造成 6 次身份顶替）。

修完后本素材 `duplicate_track_pairs`：卡尔曼 **6** / 纯 IoU 基线 **25**（后者没有这两道抑制）。

## 4. 追踪算法

### 4.1 状态与运动模型

```
x = [cx, cy, w, h, vx, vy]ᵀ   （像素，像素/帧）
```

`F` 为匀速模型；`w, h` 只做随机游走、不做速度外推——固定机位下手持物料的尺度在 1~2 s 内基本
不变，而尺度一阶差分噪声很大（框边缘抖 ±1 px 就带来 `Δw=2 px`），加速度项只会让预测框在
遮挡期膨胀/收缩、拉低 IoU。

### 4.2 关联

1. **同类别**匹配（IoU 门限 0.3），匈牙利全局最优（`linear_sum_assignment`）；
2. **第二级**：剩余孤立检测 × 正在预测态的航迹，IoU ≥ 0.8 才允许跨类配对（类别抖动救援）；
3. **匹配用预测框**：每帧先 `predict()`，再用预测位置算 IoU——这就是题面 §7 要求的
   "用预测位置参与关联"，也防交叉互锁；
4. **出生抑制**：与同类存活航迹 IoU>0.6 的检测不开新航迹。

### 4.3 生命周期

| 状态 | 判据 | 行为 |
|---|---|---|
| 新生 | 未匹配且不与同类航迹重叠 | 新 ID（单调递增，从不回收） |
| 更新 | IoU ≥ 0.3 | 卡尔曼更新，绿实线 + `ID n cls conf` |
| 预测 | `1 ≤ tsu ≤ 10` | 只预测，黄虚线 + `PREDICTED ID n k=` |
| 删除 | `tsu > 10` | 移除，ID 作废 |

## 5. Q 与 R 的实测来源（`results/noise_params.json`）

**(1) 量测噪声 R**：`r[t] = p[t] − mean(p[t-2..t+2])`，白噪声经 5 点平均后方差为 `σ²/5`：

```
Var(r) = σ²(1 − 1/5) = 0.8σ²   ⇒   σ² = Var(r)/0.8
```

实测 `Var(r)` = 0.109 / 0.080 / 0.534 / 0.355（cx/cy/w/h，MAD 稳健估计），得

```
R = [0.1360, 0.1002, 0.6678, 0.4440]  (px²)
```

即框中心噪声 σ ≈ 0.37 / 0.32 px，宽高 σ ≈ 0.82 / 0.67 px。

**(2) 过程噪声**：对连续 15 帧中心轨迹二次拟合，二次项 ×2 = 加速度，取 p90：

```
σ_a = 0.141 px/帧²
```

对照法（二阶差分扣 6R）算出的地板值是 1.00，说明加速度已接近噪声量级、差分法测不出，
所以用二次拟合的 p90——这个取舍在代码注释里写明了。

**(3) 尺寸过程噪声**：`Var(Δw) = 2σ_w² + q_w ⇒ q_w = max(Var(Δw) − 2σ_w², 0.25)`，
`σ_size = 0.5 px/帧`。

## 6. 观测不可信时怎么"少信一点"（题面 §2.2 必答）

代码里真的做了（`Track.update()`）：

```
scale  = 1 + 4·(1 − IoU) + 2·(1 − conf)
R_used = diag(R) · scale
```

IoU 越低（遮挡边缘只露出半截、框残缺）或置信度越低 → R 越大 → 卡尔曼增益越小 → 更多保留预测值；
IoU 跌破 0.3 门限则不匹配，相当于这次观测完全不采用。

## 7. 为什么不用"匀速直线硬外推"

| | 匀速外推 | 卡尔曼 |
|---|---|---|
| 速度来源 | 最近两帧差分 | 全部历史 + 协方差 |
| 权重 | 100% 信速度 | 按 P 自适应 |
| 噪声 | 差分把抖动放大 2~3 倍后直接积分 | 被 R 吸收，自适应 R 再对残缺框降权 |
| 尺度 | 通常一起外推，遮挡期框漂 | 宽高只随机游走 |
| 可解释性 | 无不确定度，说不出"还能信几帧" | P 随预测帧数增长，用来定 max_age |

**受控仿真**（`results/prediction_sim.png`，σ=1 px 检测噪声、观测 20 帧、200 次试验、沿用实测 Q/R）：

| v (px/帧) | k=1 | k=5 | k=10 | k=15 |
|---|---|---|---|---|
| 0 | 1.21 / 0.92 | 2.72 / 0.91 | 4.73 / 0.93 | 5.97 / 0.93 |
| 2 | 1.25 / 2.14 | 2.63 / 10.02 | 4.69 / 20.08 | 6.35 / 30.07 |
| 5 | 1.23 / 5.02 | 2.61 / 24.99 | 4.39 / 49.98 | 6.24 / 75.04 |
| 10 | 1.26 / 9.96 | 2.65 / 49.97 | 4.62 / 100.01 | 6.59 / 150.05 |
| 20 | 1.17 / 20.01 | 2.60 / 100.03 | 4.53 / 200.05 | 6.22 / 299.99 |

（"卡尔曼 / 原地保持"，px）

- 目标静止：原地保持 0.9 px 更优，卡尔曼 4.7 px——**不占优**，如实给出；
- 5 px/帧 运动、遮挡 10 帧：卡尔曼 4.4 px vs 原地保持 50.0 px，**误差降 11 倍**；
- 速度越快差距越大，且卡尔曼误差几乎不随 v 增长。

## 8. max_age = 10 的依据

### 8.1 人工遮挡实验（题面表 4 的 5/10/15/20 四档）

把检测链上某段窗口的检测删掉（遮挡期真实位置已知），每个 k 约 30 余个事件
（`results/occlusion_bench.csv`）：

| 遮挡帧数 k | 事件数 | ID 保持率 | 恢复首帧误差 | 遮挡末帧误差 | 首帧 IoU |
|---|---|---|---|---|---|
| 5 | 33 | **100%** | 5.62 px | 15.44 px | 0.963 |
| 10 | 32 | **96.9%** | 5.55 px | 24.15 px | 0.962 |
| 15 | 32 | **0%** | 5.20 px | 24.76 px | 0.965 |
| 20 | 29 | **0%** | 4.97 px | 22.62 px | 0.968 |

5~10 帧基本保住，15 帧起全断——分界线在 10 与 15 之间。

### 8.2 max_age 改大改小的代价（`results/max_age_sweep.csv`）

| max_age | 10 帧遮挡保持率 | 全片 ID 数 | 换号 | 身份顶替 |
|---|---|---|---|---|
| 5 | 0% | 25 | 15 | 1 |
| **10** | **96.9%** | **15** | **5** | **1** |
| 20 | 96.9% | 13 | 3 | **2** |

- 取 5：10 帧遮挡超出窗口，ID 暴涨到 25、换号 15 次；
- 取 20：保持率不升，ID 数少到 13，但身份顶替翻倍（2 次）——僵尸航迹把新物体顶替掉；
- 取 10：保持率与 20 持平，ID 与换号都明显少于 5，顶替次数更少。**10 帧是这三档里综合最稳的**。

### 8.3 时间尺度

30 fps 下 10 帧 = 333 ms，与"手挡住物料"的典型时长、以及人眼能接受"还在跟"的时长同量级。

## 9. 与纯 IoU 的对比实验（题面表 5）

同一份检测、同一套生命周期参数（max_age=10、门限 0.3），只换"有无运动模型"：

| 指标 | 纯 IoU | + 卡尔曼 |
|---|---|---|
| 分配 ID 总数 | 17 | **15** |
| 换号次数 | 5 | 5 |
| 一条航迹被换到另一物体的次数 | 0 | 0 |
| **同一物体两条 ID 的帧-对** | **25** | **6** |
| 遮挡后 ID 保持率 | 67/68 = 98.5% | 67/68 = 98.5% |
| 遮挡 ≤10 帧保持率 | **100%** | **100%** |
| 静止目标 帧间位移均值 | 0.446 px | **0.275 px** |
| 静止目标 帧间位移方差 | 0.082 px² | **0.030 px²**（降 63%） |
| 高频抖动 RMS | 3.649 px | **3.486 px** |
| 平滑滞后 | 0（定义使然） | 1.239 px |

结论要说得准确：本素材上卡尔曼的收益是**ID 更少（15 vs 17）、双胞胎少 4 倍（6 vs 25 frame-pairs）、
静止目标框的帧间位移方差降 63%**；换号次数两者持平；代价是 1.2 px 的平滑滞后。

> 说明：自然断档回放（`results/occlusion_natural.png`）本素材只有 15 个"可预测事件"，
> 且断档期间位移全部 <20 px（`[gap/moving] n=0`），因此这张图只能反映准静止目标，
> 运动预测的收益以第 7 节的受控仿真与 8.1 的人工遮挡为准。

## 10. 交叉场景防 ID 互锁（题面 §7 必答）

本素材第 43~45 秒有真实的"手机从杯子前面穿过"片段（检测层 cup↔phone 峰值 IoU **0.898**，
`demo_2_crossing.png` 取在第 1291 帧、两框 IoU 0.91）。四道措施保证不锁错：

1. **预测位置参与关联**——交叉瞬间两个框的预测位置仍然分开；
2. **全局最优匹配**（匈牙利），不是贪心；
3. **同类别约束**——不同类别的交叉根本不会互配；
4. **身份顶替指标**（`identity_steal_events`）专门检测"ID 连续但换了物体"，本片 0 次。

如实说明：交叉片段中两框**连续重叠的时长约 1.2 s**（1284–1296 / 1309–1319 / 1329–1336 三段），
短于题面要求的 3 s——3 s 是指"交叉情节时长"，实际传过去的过程约 2.5 s，但检测框在过曝/遮挡
边缘会断续，所以连续重叠不足 3 s。

## 11. 置信度与类别匹配策略（题面表 1）

- **低置信度检测**：由检测端 0.5 阈值统一把关（3.1 的扫描表是依据），追踪层不再分两级；
- **类别抖动**：先用两级匹配救援（4.2 第 2 条），救不回来就等旧航迹超时死亡，宁可断 ID 也不跨类
  强行续命——跨类硬匹配在本素材实测会造成 6 次身份顶替，比断 ID 更糟。

## 14. 已知局限

1. **相交片段连续重叠约 1.2 s（<3 s）**：传递过程约 2.5 s，但检测框在遮挡/反光边缘会断续。
3. **自然断档没有"移动中被遮挡"的样本**（`[gap/moving] n=0`）：本片遮挡都发生在准静止目标上，
   运动预测的收益只能用仿真与人工遮挡证明。
4. **手机检出率偏低**（911/2541 ≈ 36%）：手持时姿态变化大，模型（训练集是平放手机）容易漏检，
   这也是交叉片段重叠断续的原因。
5. **单目无深度**：`vx, vy` 是像素/帧，机位一动速度就不再是目标自身速度。
6. **同类目标完全重叠**仍可能换号（无 ReID 特征），不同类别不受影响。
