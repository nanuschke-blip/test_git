# M2-1 传统视觉管线：相机标定与红绿灯检测

本项目基于 OpenCV 传统视觉方法，实现了相机的单目内参标定，以及复杂光照下的红绿灯状态识别。

## 🛠️ 依赖环境
在运行代码前，请确保已安装 Python 3.10+ 及以下依赖库：
```bash
pip install opencv-python numpy pyyaml

## 🚀 一键运行指南

本项目所有代码均支持从命令行传入参数，**禁止将路径写死在代码中**，确保在任何环境下均可一键跑通。

### 1. 相机标定 (calib.py)

确保 `calib_imgs` 文件夹中有 15 张以上的棋盘格照片。运行以下命令进行标定，并生成符合规范的 yaml 文件：

```bash
python3 calib.py -i calib_imgs/ -o camera_calibration.yaml
(注：脚本内部已设定实测棋盘格单个方格物理边长为 24.0 mm，与实际打印尺寸严格对齐)

### 2. 红绿灯检测 (detect.py)
程序会读取 camera_calibration.yaml 标定文件，并支持单图、视频、摄像头三种输入源。

模式 A：摄像头实时检测

```bash
python3 detect.py -c camera_calibration.yaml -s
(运行后按 q 键退出)

模式 B：单张图片检测

```bash
python3 detect.py -i test.jpg -c camera_calibration.yaml -s
模式 C：视频文件检测

```bash
python3 detect.py -v test_video.mp4 -c camera_calibration.yaml


💡 核心算法管线与原理说明
检测模块严格遵循传统视觉的经典流水线，顺序不可颠倒，每一步均包含特定的工程目的：

采图：获取 BGR 原始图像。

去噪：使用 cv2.GaussianBlur（5x5 高斯核）平滑图像，消除传感器随机噪点。

颜色分割：将图像转换至 HSV 色彩空间。因为 RGB 混合了亮度信息，而 HSV 可将色相（H）独立，对光照变化更具鲁棒性。利用 cv2.inRange 结合实测阈值提取红、黄、绿掩码。

形态学清理：使用 5x5 核进行开运算（消除暗背景上的小白噪点）与闭运算（填补目标内部的黑洞或断裂），优化掩码质量。

轮廓查找与过滤：通过 cv2.findContours 提取边缘，并利用面积过滤（100 < 面积 < 50000）剔除环境同色干扰物（如绿毛巾）和过小的噪点。

状态判定与外接圆：利用 cv2.minEnclosingCircle 拟合最小外接圆。当多掩码命中时，按红>黄>绿的优先级及面积最大原则取主目标；若全未命中，则输出“未识别”，保证程序不崩。

🎤 现场答辩预设问题与满分回答（Q&A）
Q1：你的相机标定结果怎么样？怎么证明是准的？
答：我的标定重投影误差（RMSE）达到了 0.0807 px。这是评估标定是否可信的唯一客观指标。误差低于 0.1 像素说明内参矩阵解算极其精准。我的 fx 与 fy 数值非常接近，畸变系数 k1 量级在合理范围内，说明角点检测没有出现问题。

Q2：为什么棋盘格的物理边长是 24.0 mm？怎么来的？
答：网上通用的标准棋盘格是 25mm，但我打印出来后，用直尺实测了方格边长，发现因为打印机的边距缩放，实际物理边长为 24.0mm。为了保证物理坐标系（世界坐标系）的绝对真实，我在 camera_calibration.yaml 中严格写入了 24.0mm。

Q3：为什么颜色分割要用 HSV 而不是 RGB？
答：RGB 三个通道都混合了颜色和亮度信息，环境光一变，RGB 值全变。而在 HSV 空间中，H（色相）代表颜色本质，S（饱和度）和 V（明度）代表光照条件。锁定 H 值可以极大提升算法对光照变化的鲁棒性。我的阈值是基于实拍图利用取色器动态测定的。

Q4：形态学清理用了哪几种？核多大？解决什么问题？
答：使用了 5x5 的矩形核。使用了开运算（先腐蚀后膨胀）解决暗背景上的反光白噪点问题；使用了闭运算（先膨胀后腐蚀）解决灯珠中心过曝导致的掩码断裂和黑洞问题。

Q5：强光测试时正确率为什么大幅下降？
答：这是典型的高光溢出（Highlight Clipping）。强光导致相机 CMOS 像素饱和，原本红色的灯珠在画面中心变成纯白。在 HSV 空间中，明度（V）达到 255 极值，而饱和度（S）骤降至接近 0。由于丢失了颜色特征（S < 100），目标被算法过滤掉，导致了漏检。

Q6：如果背景有绿毛巾，被错误识别成了绿灯，怎么排除？
答：目前的兜底方案是设置了面积上下限（100~50000），并且如果同时检测到多个颜色，会按优先级或最大面积输出。若要严谨解决同色干扰，改进方向是引入空间位置约束（ROI），或者加入形状过滤（计算轮廓面积与外接圆面积的比例，判断是否接近圆形），因为红绿灯通常是规则的圆形或方形。

Q7：如果两个掩码同时命中怎么办？全都没命中怎么办？
答：如果同时命中，代码中设定了红>黄>绿的优先级，并结合面积大小选取最优轮廓。如果全都没命中，代码会输出 Status: Unrecognized，绝不会让程序崩溃（完美符合考核要求“不许崩”）。

Q8：你做了哪些鲁棒性测试？数据是怎么统计的？
答：我测试了正常室内光、强光直射、逆光/背光、暗光四种场景。每种光照下测试了至少 10 次以上（通过视频流连续抽帧），人工统计了状态正确率和中心坐标偏差，并将带标注的截图按规范存放在了 results 的四个子文件夹中。

Q9：逆光测试时，为什么外接圆的中心会发生偏移？
答：逆光下，相机的 3A 算法（自动曝光 AE）为了保留背景高光细节会拉低全局曝光，导致前景目标变暗。同时强光在镜头内部产生折射（Lens Flare），破坏了原本锐利的梯度边缘。边缘变模糊后，minEnclosingCircle 拟合出的几何中心自然会发生漂移。

Q10：运动中检测会不会有问题？镜头脏了怎么办？
答：快速移动会产生运动模糊，导致轮廓长宽比改变，可能通不过后续的圆形度过滤。镜头脏污会降低整体对比度，导致掩码破碎，影响检测精度。这也暴露了传统纯视觉方案在边界情况（Edge Cases）下的局限性，未来可考虑结合目标追踪算法（如光流法）来提升稳定性。
