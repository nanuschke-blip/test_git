# 00 考核规则与评分对照（2026-11 版方案，来自官方仓库）

> 依据：`Blake-John/22SmartCar` 的 `round1/创意组一轮考核.md`、`M1/M1展示指南.md`、`M2/M2展示指南.md`。
> 这份是**总纲**，各模块笔记（M1-1/2/3、M2-3/2-4）里另有"官方要求对照"小节。

## 1. 选做规则 1 + 1 + n

| 位置 | 内容 | 要求 | 我们的情况 |
|---|---|---|---|
| 第 1 个 1 | M0 基础 | 4 题全交 | ✅ M0-1 ~ M0-4 已交 |
| 第 2 个 1 | M1–M5 任选 1 个 | **该模块 4 题全做** | M2 做了 4 题（1/2/3/4）→ 可作主模块；M1 只做了 1/2/3（缺 M1-4） |
| n | 其余模块，建议 1–2 个 | 每模块 ≥2 题，且**必须含第 3 题** | M1 做了 M1-1/2/3，含第 3 题 ✅ → 可算 1 个 n 模块 |

**结论（现场填报）**：主攻 **M2**（4 题全做），补充 **M1**（3 题，含 M1-3）。
M1-4（调优 + FAULTS.md）没做，不要报。

## 2. 分值结构（决定时间怎么分配）

每个模块 100 分，四题 10/20/30/40（难度递增），单题按 100 计再折算。
单题评分维度：

| 维度 | 分值 | 具体看什么 | 我们的抓手 |
|---|---|---|---|
| 任务完成 | 40 | 需求点逐条覆盖、能真跑、边界处理 | 每份笔记的"官方要求对照"表逐条打勾 |
| 过程证据 | 20 | Git 提交密度与质量、踩坑记录是否可信 | M1-3 分 5 次提交；其它模块有多次提交；各 README 有"坑"章节 |
| 工程规范 | 10 | 目录结构、命名、README、无硬编码、一键复现 | 参数全部走 yaml/launch 参数；脚本 + 产物一一对应 |
| 权衡与判断 | 10 | 说清"为什么这么做、放弃了什么、何时失效" | slop 取舍、max_age 取舍、增强消融、静止目标反例 |
| 答辩 | 20 | 讲得清、能迁移、知道自己不知道什么 | 各笔记"答辩对策"章节 |

> 关键认知：**任务完成只占 40**。把"我试过什么、为什么放弃"讲出来，比多做一个功能更值钱。

## 3. 三条铁律（违反直接清零）

1. **严禁隐瞒 AI 使用**：用了 AI 就要在文档里写明"哪里/什么模块、是否逐行验证"。
2. **严禁一次提交 Git**：要多次有意义的提交，保证过程记录。
3. **严禁买卖/剽窃代码**。

### 3.1 AI 使用声明模板（贴到每个模块 README 末尾）

```markdown
## AI 使用说明（对应考核铁律 1）

- **使用范围**：文档措辞与排版；部分脚本脚手架（如绘图/统计脚本）；报错信息检索。
- **逐行核对的部分**：核心算法（低通滤波、卡尔曼预测/更新、PnP、投影变换、训练超参）
  均由本人逐行阅读并在本机复跑；对应产物见 `docs/`、`results/`，可按 README 复现。
- **未使用 AI 的部分**：数据采集与标注、实验设计与参数选择、结论与局限判断。
- **验证方式**：每条结论都能指向一次本机运行（命令写在 README 的"验证"节）。
```

### 3.2 Git 提交规范（过程证据 20 分）

- 一次提交只做一件事：`feat(M1-3): 投影节点 —— 静态 TF + 近似同步 + 投影`
- 信息里写"做了什么 + 为什么"，不要写 "update" / "fix bug"。
- 每个模块 ≥3 次提交；M1-3 已按"生成器 → 包骨架 → 节点 → 实验 → 文档"分 5 次。

## 4. M1 现场展示流程（官方指南，逐条对应我们的命令）

### M1-1（3 分钟）

```bash
ros2 run m1_nodes node_a      # 终端2
ros2 run m1_nodes node_b      # 终端3
ros2 run m1_nodes node_c      # 终端4
ros2 run m1_nodes alarm_server  # 终端1（先起）
ros2 interface show sensor_interfaces/msg/SensorData     # 4 个字段与顺序
ros2 topic hz /processed_distance                        # ≈9~10 Hz
ros2 param set /node_b_filter alpha 0.9                  # 曲线变"跳"
ros2 service call /trigger_alarm sensor_interfaces/srv/TriggerAlarm "{current_distance: 0.2}"
# 再 Ctrl+C 掉 alarm_server，等一次近距 → [WARN] 报警服务超时
```

考点：`status=1` 的那帧为什么"不参与滤波"——因为**不更新 `y_{k-1}`**，否则脏值会带偏后续几帧。

### M1-2（4 分钟）

官方指南是"**一条命令起 robot1，再起 robot2**"，所以现场用单组模式，别用默认双组：

```bash
ros2 launch m1_launch bringup.launch.py dual:=false namespace:=robot1   # 3 个节点
ros2 launch m1_launch bringup.launch.py dual:=false namespace:=robot2   # 再加 3 个
ros2 param get /robot1/node_c_alarm alarm_threshold    # 0.3
ros2 param get /robot2/node_c_alarm alarm_threshold    # 0.5
ros2 topic list | grep sensor_data                     # 两组隔离
ros2 launch m1_launch bringup.launch.py params_file:=/nope.yaml   # 一行错误，无 traceback
ros2 param set /robot1/node_b_filter alpha 0.9         # 另一组不受影响
```

> ⚠️ 直接 `ros2 launch m1_launch bringup.launch.py` 默认会起 **6 个节点**（双组）。
> 如果考官让你"先起 robot1"，一定加 `dual:=false namespace:=robot1`。

### M1-3（5 分钟）

```bash
ros2 bag play sample_bag --clock &                      # 带 --clock
ros2 run m1_projection projection_node --ros-args -p use_sim_time:=true
ros2 run tf2_ros tf2_echo camera_link laser_link        # TF 链通
# 展示 projection_1..3.png；指一个点说出它的激光距离（近红远蓝）
# 换第二套外参重跑：
python3 make_bag.py --laser-z 0.45 --camera-z 0.75 --fx 420 --frames 20 \
    --out sample_bag_nd --extrinsics extrinsics_nd.yaml
ros2 run m1_projection projection_node --ros-args -p use_sim_time:=true \
    -p extrinsics_file:=extrinsics_nd.yaml -p output_dir:=out_nondefault
```

> 题面要求"use_sim_time 切换要录屏"。**录屏没录** → 现场用两条命令对比日志代替：
> `-p use_sim_time:=true` 打 `差值≈0.01s`；`:=false` 打 `差值≈1.79e9 s` + `[WARN] 时间基准不一致`。
> 主动说明"静态 TF 与时间无关，所以图照样出"。

## 5. M2 现场展示流程（官方指南）

### M2-3（9 分钟）

1. 类别分布图 + 划分说明（**同一背景的连拍没有跨 train/test** 这句必须主动说）。
2. loss 曲线 + 一键训练命令（epoch、增强方式）。
3. 指标：mAP@0.5 / mAP@0.5:0.95 / 各类 P/R/F1 / 混淆矩阵。
4. **PyTorch vs ONNX 同批图对比**：`max|Δbox| = 3.05e-5 px`（见 `docs/consistency_result.json`）。
5. 播放自备演示视频（≥30 s，**含遮挡段**），看框/类别/置信度/FPS。

> ⚠️ 现场自查表要求 `demo/demo.mp4`（≥30 s，含 4 类 + 遮挡段）。**目前仓库里没有这个文件**，
> 必须现场补：用 `deploy_cpu.py` 跑一段含 4 类物料的视频，叠加 FPS 后存 `demo/demo.mp4`。

### M2-4（8 分钟）

1. 播 ≥30 s 视频（我们 84.7 s），展示 ID、轨迹、`PREDICTED` 虚线框。
2. 遮挡段：ID 保持 + 框变虚线 + 之后恢复。
3. 出画再入段：说明 ID 没被新目标顶掉。
4. 对比表：纯 IoU vs 卡尔曼（ID 切换、遮挡恢复率、静止抖动）。
5. 报 R 实测方法（`derive_noise.py`：5 点滑窗残差 ÷0.8 → `[0.136,0.100,0.668,0.444]`）与 Q 量级（`σ_a=0.141`）。
