## 0.6 三十秒开场

「我用 15 张 9×6 棋盘格做标定，方格实测 24 mm，重投影误差 0.0807 px；检测端走

## 1. 重点（考官会盯的 4 件事）

1. **24.0 mm 是实测的**，不是照抄网上的 25 mm（打印缩放会变）；
2. **RMSE 0.08 px** 是标定可信度的唯一客观指标；
3. 检测管线**顺序不能乱**（去噪→HSV→形态学→轮廓→圆）；
4. 强光 20% 不许藏，要能解释"高光溢出 → S 掉到 0 → 被 S>100 阈值滤掉"。

## 2. 知识点

### 2.1 针孔模型与内参

```
u = fx·X/Z + cx,  v = fy·Y/Z + cy
K = [[fx,0,cx],[0,fy,cy],[0,0,1]]
```

`fx = f/dx`（焦距 ÷ 像元尺寸）。我的结果：fx 1221.1、fy 1223.1（很接近，说明像元近似正方形）、
cx 941.7、cy 547.4（1920×1080 的中心偏左，主点不一定在几何中心）。

### 2.2 畸变模型

径向（桶形/枕形）+ 切向（镜头与像面不平行）：

```
x' = x(1 + k1 r² + k2 r⁴ + k3 r⁶) + 2p1xy + p2(r²+2x²)
y' = y(1 + k1 r² + k2 r⁴ + k3 r⁶) + p1(r²+2y²) + 2p2xy
```

我的 k1 = −0.0141（轻微桶形）、k2 = 0.1325、p1/p2 都在 1e-4 量级（可忽略）、k3 = −0.259。

### 2.3 张正友标定（棋盘格）

1. 每张图求**单应** H（>=4 个角点，DLT + 归一化）；
2. 由 H 的约束（旋转列正交、长度为 1）线性解出 `B = K^{-T}K^{-1}`，再分解得 K；
3. 用 K 反解每张图的 R、t；
4. **LM 全局优化**（重投影误差最小），并可再联合优化畸变系数。
`cv2.calibrateCamera` 就是这条流程，返回的 `ret` 就是 RMSE。

**RMSE 0.08 px 意味着什么**：角点重投影平均偏差不到 0.1 像素（亚像素级），
说明角点检测与内参一致，标定可用。

### 2.4 传统视觉检测

| 步骤 | 作用 | 我们的参数 |
|---|---|---|
| GaussianBlur | 去传感器随机噪点 | 5×5 |
| BGR→HSV | H 分离色相，抗光照变化 | — |
| `inRange` | 红/黄/绿掩码 | H 区间实测，S>100，V>70 |
| 开运算 | 去掉背景小白噪点 | 5×5 矩形核 |
| 闭运算 | 补灯珠内部空洞/断裂 | 5×5 矩形核 |
| `findContours` | 提轮廓 | `RETR_EXTERNAL` |
| 面积过滤 | 去掉过小噪点与同色大块 | 100 < area < 50000 |
| `minEnclosingCircle` | 拟合最小外接圆，给中心与半径 | — |
| 优先级 | 红 > 黄 > 绿，多命中取主目标 | — |

**为什么 HSV 不是 RGB**：RGB 三通道都混了亮度；HSV 里 H 是色相、S/V 是光照，
灯变亮时 H 基本不变，阈值才稳定。

## 3. 算法逻辑（两条链）

```
标定：calib_imgs/*.jpg → findChessboardCorners(9x6) → cornerSubPix 亚像素
      → calibrateCamera(24.0mm) → K, dist, RMSE → camera_calibration.yaml

检测：frame → GaussianBlur(5x5) → BGR2HSV → 三个 inRange
      → 开/闭运算 → findContours → 面积过滤 → minEnclosingCircle
      → 画圆 + 写 (cx,cy) 与面积 + 状态优先级判定 → 输出
```

## 4. 实测数据

**标定**（`camera_calibration.yaml`）：1920×1080，15 张，9×6，方格 24.0 mm，
**RMSE 0.0807 px**，fx 1221.107 / fy 1223.090 / cx 941.677 / cy 547.367，
k1 −0.01411，k2 0.13251，p1 −3.74e-5，p2 −0.00133，k3 −0.25948。

**鲁棒性**（人工统计，非逐帧标注）：

| 光照 | 状态正确率 | 中心误差 | 现象 |
|---|---|---|---|
| 正常室内 | 100% | <3 px | 轮廓完整，外接圆稳定 |
| 强光直射 | **20%** | 无法计算 | 中心过曝纯白，S→0，被阈值滤掉 |
| 逆光/背光 | 85% | <8 px | 光晕使边缘模糊，圆心漂移 |
| 暗光/黄昏 | 95% | <5 px | 噪点增加，发光体仍可分出 |

## 5. 经验总结（踩过的坑）

1. **棋盘格边长必须实测**：网上写 25 mm，打印出来量是 24.0 mm；差 4% 会直接让
   所有距离系统性偏 4%。
2. **面积下限从 500 降到 100**：手机屏幕上的灯珠像素很小，500 会全滤掉。
3. **强光下不是"检测不准"，是"颜色没了"**：CMOS 饱和 → RGB 都到 255 → S 掉到 0，
   阈值里 `S>100` 直接把目标删了。这是物理原因，不是调参能救的。
4. **同色干扰（绿毛巾）**：纯颜色阈值没有空间/形状约束，只能靠面积上下限和优先级兜底。
5. **暗光下的 AWB 会把黄推成红**：低照度白平衡补偿拉高 R/G，H 向 0°/180° 漂。

## 6. 答辩对策

**Q1：怎么证明标定是准的？**
A：RMSE 0.0807 px，亚像素级；fx 与 fy 只差 0.16%，说明像元近似方形；k1 量级 −0.014
符合普通 USB 摄像头的轻微桶形。再补一句：可以用已知距离的靶标反算距离验证（M2-2 做了，0.3/0.5/0.8 m 误差 ≤2%）。

**Q2：为什么用 24.0 mm 而不是 25？**
A：打印有缩放，尺子量的才是真值；把 24 写进 yaml 的 `square_size_mm`，标定和位姿都用它。

**Q3：为什么先高斯再 HSV？**
A：先去噪能减少 HSV 掩码里的孤立噪点，形态学就不需要更大的核；顺序反了会把噪点也增强。

**Q4：开运算和闭运算各解决什么？**
A：开（先腐蚀后膨胀）去掉背景反光小白点；闭（先膨胀后腐蚀）补灯珠内部过曝造成的黑洞。

**Q5：面积阈值 100~50000 怎么来的？**
A：下限 100 ≈ 屏幕上最小灯珠的像素面积；上限 50000 ≈ 排除整块背景（绿毛巾/墙）。
代价是同色大物体仍可能误检，改进方向是加圆形度（4πA/P²）与 ROI。

**Q6：强光下 20% 怎么救？**
A：短期靠降低曝光/加 ND 滤光；算法上可加 CLAHE 或换成"局部高光检测 + 形状判别"，
但它已经丢失了颜色信息，纯颜色法必然失效——这属于方法边界，要讲清楚而不是硬调参。

**Q7：如果现场换一个相机？**
A：重新跑 `calib.py`（15 张、同规格板），因为内参与畸变是相机个体属性；检测阈值与内参无关，不用重调。

**Q8：5 种失效里哪条最致命？**
A：强光饱和（直接漏检）和同色误检（假阳性）最致命；逆光只是精度下降，暗光只是噪点。
按"漏检 > 误检 > 精度下降"排序讲，能显示你懂工程优先级。
