# 一、M1-1 三节点链路 + 动态配参（约 3 分钟）

## 1.1 命令

```bash
cd ~/m1_ws && source /opt/ros/humble/setup.bash && source install/setup.bash

# 终端1~4（服务端先起）
ros2 run m1_nodes alarm_server
ros2 run m1_nodes node_a
ros2 run m1_nodes node_b
ros2 run m1_nodes node_c
```

```bash
# 核验（第 5 个终端）
ros2 node list                                          # 4 个节点
ros2 topic list | grep -E "sensor_data|processed|trigger"
ros2 topic hz /processed_distance                       # ≈10 Hz
ros2 interface show sensor_interfaces/msg/SensorData    # 4 字段顺序
ros2 interface show sensor_interfaces/srv/TriggerAlarm
ros2 param set /node_b_filter alpha 0.9 && ros2 param get /node_b_filter alpha
ros2 param get /node_c_alarm alarm_threshold            # 0.3
ros2 param get /node_c_alarm service_timeout            # 1.0
ros2 service call /trigger_alarm sensor_interfaces/srv/TriggerAlarm "{current_distance: 0.2}"
# 最后：Ctrl+C 掉 alarm_server 那个终端，等 1~2 秒
#   -> [WARN] 报警服务超时 (1.0 秒无响应)
```

## 1.2 要念的数字

| 项 | 值 |
|---|---|
| 消息字段（顺序固定） | `float32 distance` / `string unit` / `builtin_interfaces/Time stamp` / `uint8 status` |
| 服务 | `float32 current_distance` → `bool success` / `string message` |
| 话题 | `/sensor_data` → `/processed_distance`；服务 `/trigger_alarm` |
| 参数 | `alpha` 0.3、`alarm_threshold` 0.3、`service_timeout` 1.0 |
| 频率 | `ros2 topic hz /processed_distance` **≈10 Hz**（无效数据 5% 被丢弃） |
| 滤波 | `y_k = α·x_k + (1−α)·y_{k−1}`，α 从 0.3 调到 0.9 曲线明显变"跳" |

## 1.3 追问

**Q：`status != 0` 的帧为什么不参与滤波？**
「不只是不发布——**不更新 `y_{k-1}`**。如果只跳过发布却更新状态，9.99 m 的超量程脏值会把滤波器带偏好几帧。」

**Q：为什么服务端单独一个进程？**
「考官要"杀掉服务端"看超时；服务端和客户端同进程就杀不了客户端，这条验收没法做。」

**Q：超时是怎么做的？为什么不用 `sleep`？**
「`call_async` 立刻返回，配一个 0.1 s 的看门狗定时器，在途请求超过 1 s 就打警告并释放标志。
在回调里 `sleep` 会卡死单线程 executor，连超时判断本身都不会触发。」

**Q：改 alpha 能看到什么变化？**
「alpha 越大越信新观测：0.3 时曲线平滑、滞后大；0.9 时几乎跟着原始值跳。时间常数 τ = Δt(1−α)/α。」

**Q：为什么频率是 10 Hz 不是别的？**
「节点 A 定时器 0.1 s；B 丢掉约 5% 的 `status!=0`，所以下游接近 10 Hz。」

# 二、M1-2 Launch 编排（约 4 分钟）

## 2.1 命令

```bash
cd ~/test_git/round1/M1/M1-2 && source /opt/ros/humble/setup.bash && source install/setup.bash

# ① 一条命令起两组（对应验收第 1 条）
ros2 launch m1_launch bringup.launch.py

# ② 6 个节点
ros2 node list | sort

# ③ 同一份 launch、不同命名空间取到不同参数
ros2 param get /robot1/node_b_filter alpha          # 0.3
ros2 param get /robot2/node_b_filter alpha          # 0.6
ros2 param get /robot1/node_c_alarm alarm_threshold # 0.3
ros2 param get /robot2/node_c_alarm alarm_threshold # 0.5

# ④ 话题隔离
ros2 topic list | grep -E "sensor_data|processed_distance" | sort

# ⑤ 参数文件不存在 -> 清晰报错
ros2 launch m1_launch bringup.launch.py params_file:=/nope.yaml
#   [M1-2][ERROR] 参数文件不存在: /nope.yaml（请检查 params_file:=... 路径）

# ⑥ 只起一组（考官若要求"先起 robot1"）
ros2 launch m1_launch bringup.launch.py dual:=false namespace:=robot1
```

## 2.2 要念的数字

| 项 | 值 |
|---|---|
| 参数文件 | `params_robot1.yaml`（alpha 0.3 / 阈值 0.3）、`params_robot2.yaml`（**alpha 0.6** / 阈值 0.5） |
| 启动结果 | `/robot1/*` 与 `/robot2/*` 共 **6 个节点** |
| 隔离 | `/robot1/sensor_data`、`/robot2/sensor_data` … |
| 启动顺序 | C 在 B 之后（`OnProcessStart` + `TimerAction(1.0)`） |
| 错误处理 | 一行 `[M1-2][ERROR]`，**无 Python 栈回溯** |

## 2.3 追问

**Q：YAML 的 key 为什么写 `/**/node_b_filter`？**
「带命名空间后节点全名是 `/robot1/node_b_filter`；`node_b_filter` 这种相对 key 匹配不到。
`**` 匹配任意命名空间层级，所以一份文件在 robot1/robot2 都生效。」

**Q：C 怎么保证在 B 之后启动？**
「注册 `OnProcessStart(target_action=node_b)`，触发后先打日志、再 `TimerAction(1.0)` 才 spawn C。
C 不在顶层 action 列表里，只由事件触发。」

**Q：缺文件为什么不抛栈？**
「在 `OpaqueFunction` 里校验（launch 展开期执行），失败就往 stderr 打一行再 `EmitEvent(Shutdown)`，
不用 `raise`——`raise` 会打印整段 traceback。」

**Q：`use_sim_time` 怎么传的？**
「launch 参数 `use_sim_time` 传给每个节点；（yaml 里也有 `/**` 全局块兜底）。」

**Q：官方写"滤波窗口大小"，你用的是 alpha？**
「M1-1 契约把滤波定义为 `y=αx+(1−α)y_{k−1}`，一阶 IIR 没有"窗口"概念，α 就是它的唯一参数；
若按滑动平均实现才需要 window，两者时间常数可换算 τ=Δt(1−α)/α。」

# 三、M1-3 时间与坐标（约 5 分钟）

## 3.1 命令

```bash
cd ~/test_git/round1/M1/M1-3 && source /opt/ros/humble/setup.bash && source install/setup.bash

# ① 回放（必须带 --clock）+ 投影节点
ros2 bag play sample_bag --clock
ros2 run m1_projection projection_node --ros-args -p use_sim_time:=true

# ② TF 链
ros2 run tf2_ros tf2_echo base_link camera_link     # [0.100, 0.000, 0.300]
ros2 run tf2_ros tf2_echo camera_link laser_link

# ③ 三张效果图
xdg-open projection_1.png & xdg-open projection_2.png & xdg-open projection_3.png

# ④ 换一套非默认外参重跑（证明没写死）
python3 make_bag.py --frames 20 --laser-z 0.45 --camera-z 0.75 --fx 420 \
    --out sample_bag_nd --extrinsics extrinsics_nd.yaml
ros2 run m1_projection projection_node --ros-args -p use_sim_time:=true \
    -p extrinsics_file:=extrinsics_nd.yaml -p output_dir:=out_nondefault

# ⑤ use_sim_time 对比（没录屏，用日志代替）
ros2 run m1_projection projection_node --ros-args -p use_sim_time:=false
#   差值≈1.79e9 s + [WARN] 时间基准不一致
```

## 3.2 要念的数字

| 项 | 值 |
|---|---|
| TF | `map→odom→base_link→{laser_link,camera_link}`，全部静态、数值读 yaml |
| 同步 | `ApproximateTimeSynchronizer`，slop **0.06 s**、queue **50** |
| slop 实验 | 5 ms→32%、10 ms→52%、20 ms→98%、**30 ms→100%**（相机 27 Hz，最近帧上限 20.8 ms） |
| 投影 | 近红远蓝，点落在图像中心偏下（v≈250~300），每帧约 20~29 个点 |
| use_sim_time | true 差 **0.009 s**；false 差 **1.79e9 s** + WARN |

## 3.3 追问

**Q：为什么用 ApproximateTime 不用精确同步？**
「两路时间戳不同源、频率也不同（10 Hz vs 27 Hz），精确同步一帧都配不上。」

**Q：slop 为什么取 60 ms？**
「30 ms 就饱和到 100%（相机半周期 18.5 ms + 抖动 = 20.8 ms 上限），取 60 ms 是留相机丢帧的余量；
再大（>100 ms）会配到差一整个雷达周期的帧，时间对齐质量下降。」

**Q：投影点为什么在图像中心偏下？**
「相机装在激光平面之上 0.10 m，激光点在相机下方，`v = fy·0.10/X + cy > cy`。」

**Q：公式里最容易错的是哪一步？**
「机体→光学系的旋转 `R=[[0,-1,0],[0,0,-1],[1,0,0]]`，写成了转置就会上下颠倒/左右镜像。」

**Q：use_sim_time 配错会怎样？**
「节点时钟是墙钟、数据是仿真时间，差 17 亿秒，打 WARN。**但静态 TF 与时间无关，所以图照样能出**
——换成动态 TF 或依赖 `now()` 的逻辑就会直接失败。」

**Q：换外参为什么不怕？**
「所有数值都从 `extrinsics.yaml` 读，代码里没有 0.15/0.20/500 这种常数；换 yaml 重跑即可。」
