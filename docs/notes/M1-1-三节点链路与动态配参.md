
## 1. 任务分解

要求是一条最小的数据闭环：**传感器 → 滤波 → 报警**，三个节点必须独立进程。

```
┌──────────────┐   /sensor_data            ┌──────────────┐
│ node_a_sensor│  SensorData(自定义 msg)    │ node_b_filter│
│  10 Hz 定时器 │ ────────────────────────► │ 一阶低通滤波  │
└──────────────┘                           └──────┬───────┘
                                                  │ /processed_distance
                                                  │ std_msgs/Float32
                                                  ▼
                                           ┌──────────────┐   /trigger_alarm
                                           │ node_c_alarm │ ───────────────► ┌──────────────┐
                                           │ 阈值判断+超时 │  TriggerAlarm.srv │ alarm_server │
                                           └──────────────┘ ◄─────────────── └──────────────┘
```

四个可执行文件、三个"业务节点" + 一个服务端。**服务端单独成进程是刻意的**：验收要
"杀掉服务端看节点 C 是否超时"，若服务端与客户端同进程，杀掉服务端等于把客户端也杀了，
这条验收就无法进行。

## 2. 为什么选 topic / service / param 各一处

| 通信方式 | 语义 | 本题用它做什么 | 为什么不用别的 |
|---|---|---|---|
| **Topic**（发布/订阅） | 单向、异步、多对多、无返回 | A→B、B→C 的数据流 | 数据是连续流，不需要应答；用 service 会引入请求-响应开销和阻塞 |
| **Service**（请求/响应） | 双向、同步语义（可用异步客户端）、有返回值 | C→报警服务端 | 报警需要"确认执行成功"这个返回值；用 topic 拿不到结果 |
| **Parameter**（参数） | 节点内配置，可运行时读写 | `alpha`、`alarm_threshold`、`service_timeout` | 参数是"配置"而非"数据流"，天然支持 `ros2 param set` 动态改 |
| Action（未用） | 长任务 + 反馈 + 可取消 | 本题不需要 | 报警是毫秒级动作，没有中间反馈需求 |

## 3. 自定义接口（msg / srv）是怎么变成可 import 的模块的

链路是这样的：

1. `sensor_interfaces/msg/SensorData.msg` 写字段；
2. `CMakeLists.txt` 里 `rosidl_generate_interfaces(${PROJECT_NAME} "msg/..." "srv/..." DEPENDENCIES builtin_interfaces)`；
3. `package.xml` 里必须有 `rosidl_default_generators`（buildtool）、`rosidl_default_runtime`（exec）、
   `<member_of_group>rosidl_interface_packages</member_of_group>`，用到 `builtin_interfaces` 时还要 `<depend>`；
4. `colcon build` 时 rosidl 生成 C++ 头文件与 **Python 模块**（`sensor_interfaces/msg/__init__.py` 等），
   装进 `install/sensor_interfaces/`；
5. 节点里 `from sensor_interfaces.msg import SensorData` 才能工作——前提是 `source install/setup.bash`
   把该包的 Python 路径加进 `PYTHONPATH`。

**关键点**：接口包必须是 `ament_cmake`（不是 `ament_python`），因为要跑代码生成；
并且 `<depend>builtin_interfaces</depend>` 不能漏，否则 `builtin_interfaces/Time` 解析失败。

## 4. 一阶低通滤波（核心算法）

### 4.1 差分方程

```
y_k = α·x_k + (1-α)·y_{k-1},   0 < α ≤ 1
```

含义：本次输出 = 本次测量占 α 权重 + 上次输出占 (1-α) 权重。α 越小越平滑、越滞后。

### 4.2 从连续系统推过来

连续一阶低通的传递函数：

```
H(s) = 1 / (1 + τs)
```

用后向差分离散化（`s ≈ (1 - z⁻¹)/T`，T 为采样周期）：

```
y_k = y_{k-1} + (T/τ)·(x_k - y_{k-1})
   ⇒ α = T / (τ + T)   ⇔   τ = T·(1-α)/α
```

- 采样 10 Hz（T = 0.1 s）、α = 0.3 时，τ = 0.1×0.7/0.3 ≈ **0.233 s**；
- 截止频率 `f_c = 1/(2πτ)` ≈ **0.68 Hz**，即高于约 0.7 Hz 的抖动被压掉；
- 阶跃响应到达 63% 需要 τ，到达 95% 约 3τ。

这个换算是"α 到底意味着什么"的标准答案：**α 与时间常数一一对应**，
α=0.9 ⇔ τ≈0.011 s（几乎不平滑，跟随快），α=0.1 ⇔ τ=0.9 s（很平滑，滞后大）。

### 4.3 为什么用一阶低通而不是别的

| 方案 | 特点 | 本题取舍 |
|---|---|---|
| 滑动平均 | 需要缓存 N 个样本，N 越大越平滑，但延迟固定为 N/2 帧 | 实现更重，且"系数"不是单个可调量，不利演示动态配参 |
| 中值滤波 | 抗脉冲噪声强（适合离群点） | 对连续高斯抖动效果一般，且非线性、不可用单一系数调节 |
| 一阶 IIR（本题） | 只需上一帧输出，单参数 α 即可调平滑度，计算量 O(1) | **选它**：与"α 必须是可动态修改的 ROS 参数"这个考核点天然契合 |

### 4.4 无效数据怎么处理

题面要求 `status != 0` 不参与滤波。正确做法是**直接 return，不更新 y_{k-1}**：

```python
if msg.status != 0:
    self.get_logger().warn(...)
    return          # 关键：既不输出，也不让脏数据污染历史状态
```

如果只是"不发布但更新状态"，脏值（例如超量程的 9.99 m）会把滤波器带偏好几帧。

### 4.5 首帧初始化

`y_{-1}` 没有定义。若初始化为 0，前几帧会从 0 爬升，出现假的"远距离"。所以第一帧直接
`y = x`（等价于"滤波器已收敛到当前值"）。

## 5. ROS 参数系统（动态配参）

三个动作缺一不可：

```python
self.declare_parameter('alpha', 0.3)                       # 1) 声明（不声明则 set 会被拒绝）
self.alpha = self.get_parameter('alpha').value             # 2) 读取
self.add_on_set_parameters_callback(self.cb)               # 3) 注册改动回调
```

要点：

- **必须 `declare_parameter`**：ROS 2 默认不允许给未声明的参数赋值，`ros2 param set` 会报
  "parameter not declared"；
- `add_on_set_parameters_callback` 注册的回调**在参数真正生效前**被调用，返回
  `SetParametersResult(successful=True/False)` 决定"接受还是拒绝"——这也是做参数合法性校验的位置
  （比如拒绝 `alpha > 1` 或 `alpha <= 0`）；
- 回调里要**同步更新节点内部缓存**（`self.alpha = p.value`），否则参数存储变了、算法还用旧值；
- 参数类型在声明时确定（`0.3` → double），之后 `set` 的必须是同类型，否则被拒。

节点 C 同理：`alarm_threshold`、`service_timeout` 也注册了回调，改完立即影响下一次报警判断。

## 6. 异步服务调用与"不阻塞的超时"

### 6.1 为什么不能同步等

`rclpy` 默认单线程 executor：所有订阅回调、定时器回调、服务回调**都在同一个线程里排队执行**。
如果在回调里 `time.sleep(1)` 或用同步 `call()` 死等，整个 executor 被卡住：

- 定时器不再触发 → 连"超时判断"本身都不会发生；
- 其它订阅停摆 → 数据丢弃、时间戳错乱。

### 6.2 正确做法：future + done_callback + 定时器

```python
self.future = self.cli.call_async(req)          # 立即返回，不阻塞
self.future.add_done_callback(self._on_response)  # 有结果时被调用
self._timer = self.create_timer(self.timeout, self._on_timeout)  # 到点检查
```

- `_on_response(fut)`：正常返回时取 `fut.result()`，并取消定时器；
- `_on_timeout()`：定时器到点，若 `fut` 还没 `done()` → 打印 `[WARN] 报警服务超时`，
  取消定时器、释放 `pending`；
- 两者都要 `cancel` 定时器，保证"谁先到谁收尾"，不会重复告警。

### 6.3 两个易错点

1. `create_timer` 是**周期**定时器，不是一次性的；超时分支必须自己 `cancel()`，否则每秒重复打印。
2. 定时器对象要在两个回调方法**定义之后**再创建（Python 里函数名必须先存在），
   或用 `self._timer` 属性让回调在运行时再取。

### 6.4 限流

10 Hz 数据在距离持续 < 0.3 m 时每 100 ms 就会进一次回调。用 `pending` 标志保证同一时刻
最多一个在途请求：发起时置 `True`，超时或收到响应时置 `False`。否则请求会堆积，
服务端被打爆、日志也会刷屏。

### 6.5 服务端不在时会怎样

`call_async` 不会抛异常，请求会挂起等发现服务；1 秒内服务端出现则正常返回，超过则触发超时
分支打印警告——正好是考核第 4 条要看到的行为。

## 7. QoS 与队列深度

`create_publisher(..., 10)` / `create_subscription(..., 10)` 里的 `10` 是 **history depth**
（KEEP_LAST 队列长度），不是频率。含义是"来不及处理时最多缓存 10 条，超过丢最旧的"。

本题数据是 10 Hz 的小消息，深度 10 足够；如果要做高可靠传输，需要显式指定
`QoSProfile(reliability=RELIABLE, depth=...)`，默认是 RELIABLE + KEEP_LAST。

## 8. 构建与运行环境

- **colcon**：ROS 2 的构建工具，按拓扑顺序编译 `src/` 下的包；接口包被依赖包自动排在前面。
- **overlay**：`source install/setup.bash` 把本工作空间的包叠加到 `/opt/ros/humble` 之上；
  不 source 就找不到自定义消息。
- **`--symlink-install`**：Python 包用符号链接安装，改 `.py` 立即生效；不加则必须重新 build。
- **`package.xml` 的 build_type**：纯 Python 节点用 `ament_python`，接口包必须 `ament_cmake`。

## 10. 十个性价比最高的坑

1. 忘了 `source install/setup.bash` → `ModuleNotFoundError: sensor_interfaces`；
2. 没加 `--symlink-install`，改完代码没重新 build，行为不变；
3. 参数没 `declare_parameter`，`ros2 param set` 报 not declared；
4. 参数回调里没同步内部变量，参数变了算法不变；
5. 用同步 `call()` / `sleep()` 判超时，把 executor 卡死；
6. 定时器不 cancel，超时日志每秒刷一条；
7. `status != 0` 只跳过发布、却更新了滤波状态，脏数据污染后续输出；
8. 首帧用 0 初始化，出现假的"远距离→近距"跳变；
9. 服务端和客户端写在同一个进程，无法演示"杀服务端"；
10. 接口包 `package.xml` 漏 `rosidl_default_runtime` 或 `builtin_interfaces`，编译时报找不到类型。

## 11. 可以继续扩展的方向

- 把报警改成 **Action**，支持"持续报警 + 可取消 + 反馈音量"；
- 节点 B 增加**参数文件**（`params.yaml` + `--ros-args --params-file`），做多套配置切换；
- 用 **LifecycleNode** 管理节点启停，避免运行时改参数导致状态不一致；
- 引入**传感器噪声模型**（高斯 + 偶发离群点）与**中值+低通**级联滤波，对比 RMSE；
- 用 `ros2 bag record` 录一段数据，做离线回放与回归测试；
- 用 **launch 文件**一次拉起四个节点，并给节点加命名空间/remap，支持多套链路并行。
