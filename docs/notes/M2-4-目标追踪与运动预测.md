## 2. 知识点

### 2.1 多目标追踪（MOT）的基本框架

```
检测（每帧） → 预测（卡尔曼） → 关联（代价矩阵 + 匈牙利） → 更新（卡尔曼校正） → 生命周期管理（新建/删除）
```

- **TBD（track-by-detection）**：追踪不自己找目标，完全依赖检测；检测漏了靠预测顶住。
- **data association**：把"这一帧的检测框"和"上一帧的轨迹预测框"配对，本质是一个**二分图
  最大权匹配**问题，常用匈牙利算法（`scipy.optimize.linear_sum_assignment`）。
- **门限（gate）**：不是所有配对都允许——IoU 低于阈值的直接判"不匹配"，避免乱点鸳鸯。

### 2.2 卡尔曼滤波（本题的核心数学）

状态向量（6 维）：

```
x = [cx, cy, w, h, vx, vy]^T
```

- 匀速（CV）模型：位置按速度外推，速度保持不变；
- 宽高**只做随机游走**（不加宽高速度），因为尺度变化主要由检测噪声驱动，外推反而放大误差。

预测：

```
x' = F x
P' = F P F^T + Q
```

更新：

```
K  = P' H^T (H P' H^T + R)^{-1}
x  = x' + K (z - H x')
P  = (I - K H) P'
```

其中 `H` 只观测 `[cx, cy, w, h]`，`vx/vy` 靠滤波器自己推。

### 2.3 Q 与 R 的物理含义

- **R（观测噪声）**：检测框抖动有多大。检测越差（IoU 低、置信度低），R 应越大；
- **Q（过程噪声）**：目标机动有多强。用加速度方差 σ_a 构造（`Q = σ_a² · G G^T`）；
- 两者比值决定"信预测还是信观测"：R 大 → 更信预测（平滑、滞后）；Q 大 → 更信观测（跟得快、抖）。

### 2.4 常用追踪器对比（被问到时能说）

| 方法 | 关联依据 | 优点 | 缺点 |
|---|---|---|---|
| SORT | IoU + 匈牙利 + 卡尔曼 | 极简、快 | 无外观特征，遮挡久了就换 ID |
| DeepSORT | 外观 embedding + 马氏距离 + 级联匹配 | 抗遮挡、抗交叉 | 要 ReID 网络，CPU 上慢 |
| ByteTrack | 高低分检测两轮关联 | 召回高、无需外观 | 依赖检测质量，参数多 |
| **本题** | IoU + 两级匹配 + 自适应 R | 轻量（纯 CPU）、可解释、每步能对应到公式 | 无外观特征，长遮挡会丢 |

### 2.5 评价指标（自建，因为无真值标注）

真实 MOT 数据集用 MOTA / MOTP / IDF1，但这题没有逐帧真值，所以用"伪真值 + 一致性指标"：

| 指标 | 定义 | 说明 |
|---|---|---|
| ID switches | 同一伪轨迹上 ID 变化的次数 | 越少越好 |
| identity steal | 一条轨迹的 ID 被另一条"抢走"（fragment-aware） | 比 switch 更严格 |
| duplicate pairs | 同一帧里同一物体被两个 ID 覆盖的帧-对数 | 衡量"双胞胎" |
| occlusion keep rate | 断档后能否用原 ID 接回 | 遮挡能力的直接体现 |
| jitter | 相邻帧框中心的位移波动 | 平滑度 |
| static drift/var | 静止目标的位移方差 | 抖动抑制 |
| lag | 轨迹与检测的相位滞后 | 平滑的代价 |

**伪真值怎么来**：先用检测的时空连续性把同一物体的框串成"stream"，对每个 stream 取中位数
作为参考轨迹，再用它评判追踪结果。这是"相对一致"，不是绝对真值——报告里明确写了。

## 3. 算法逻辑（`tracker.py::process_frame`）

```
输入：本帧检测框 dets（clsid, conf, box）
1. 预测：所有轨迹 kf.predict() → 预测框
2. 代价矩阵：IoU(track_pred, det)；IoU < 0.3 的置为不可匹配
3. 第一级：同类匈牙利（class-aware），匹配上的更新
4. 第二级：剩余检测 × "处于预测态"的轨迹，IoU ≥ 0.8 才允许跨类配对
   （解决检测类别抖动导致的换号/双胞胎）
5. 重复检测抑制：同类 IoU > 0.6 不再新建轨迹
6. 未匹配的检测 → 新建轨迹（ID 单调递增，不回收）
7. 未匹配的轨迹 → miss_count++；超过 max_age(10) 删除
8. 自适应 R：scale = 1 + 4(1 − IoU) + 2(1 − conf)，R = diag(base_R · scale)
9. 画图：实线框=更新，虚线框=PREDICTED(k=)，青框=下一帧预测，尾迹+位移
```

**为什么两级匹配**：同类优先可以避免"杯子被识别成手机"时的错误关联；但对**类别抖动**（同一
物体这帧叫 cup、下帧叫 phone）需要救援，所以第二级只允许"预测态轨迹 + 高 IoU（≥0.8）"的
跨类配对，阈值故意设得很严，避免乱配（试过 0.7，导致 6 次身份顶替，回退到 0.8）。

## 5. 经验总结（踩过的坑）

1. **重复检测比漏检更致命**：早期一个物体会被两条 ID 抢（phone/tissue IoU 0.98），
   双胞胎帧-对高达 25。第一次尝试"跨类 IoU≥0.7 直接匹配"，结果产生 **6 次身份顶替**；
   回退成"两级匹配 + 严格跨类救援（0.8）"后，双胞胎降到 6、顶替 0。
   **教训：放宽一个阈值之前，先想清楚它会不会把"两个物体"配成一个。**
2. **指标要先定义清楚**：一开始用"ID 变化次数"衡量身份错误，但断轨重连被误判成顶替。
   后来把指标改成 **fragment-aware**（用 stream 中位数判断两条 ID 是否其实同一个物体），
   才得到可信的 `identity_steal_events`。
3. **视频与检测必须同源**：换过 5 次素材，每次都要重跑检测，否则"框和画面差半秒"。
   现在 `check` 帧数一致性（视频 / tracked.mp4 / iou_only.mp4 / json 全是 2541）。
4. **关键帧要自动挑，不能手点**：`capture_demos.py` 用滑窗找"同时 ≥3 条轨迹"、
   "最长静止段"、"遮挡时刻"、"出画再入"，避免挑到 frame 0 这种没信息的帧。
5. **仿真不能替代实测，但能证明机制**：遮挡 bench 是人工遮挡（明确标注"受控实验"），
   自然断档曲线只反映准静止目标（`gap/moving n=0`），两者不能混着说。
6. **承认反例**：静止目标上卡尔曼不如"原地保持"（4.73 vs 0.93 px），因为滤波器把检测抖动
   当成运动。改进方向是加"静止检测 + 冻结速度"。
7. **参数要有出处**：R、σ_a、max_age、IoU gate 全都有脚本和 sweep 数据，不写"调出来的"。

## 6. 答辩对策

### 6.1 技术追问（高频）

**Q1：为什么用卡尔曼 + 匈牙利，不上 DeepSORT/ByteTrack？**
A：三个约束：纯 CPU、要可解释、要能被追问到公式。DeepSORT 需要 ReID 网络（CPU 上单帧
多 20~30 ms）且本场景只有 6 类桌面物体、外观差异小，ReID 收益有限；ByteTrack 依赖高低分
两轮检测，而我的检测器阈值已经是 0.5（再降空帧激增：0.15 时空帧 24 帧、0.6 时 245 帧）。
选卡尔曼 + 匈牙利是"够用 + 每步都能解释"。

**Q2：为什么状态是 6 维，不加加速度/宽高速度？**
A：10 Hz、桌面场景，目标基本匀速；加加速度会让状态维度到 9，Q 矩阵难标定，且加速度在
噪声里几乎不可观。宽高变化主要来自检测框抖动而不是真实尺度变化，所以只让 w/h 随机游走
（Q 里给一个小方差），不外推。

**Q3：Q 和 R 怎么定的？**
A：不是手调。`derive_noise.py` 做两件事：
- **R**：对每个检测框做 5 点滑动平均，取残差的标准差再除以 0.8（因为 MA 本身会削掉部分噪声），
  得到 `R = [0.136, 0.100, 0.668, 0.444]`（对应 cx, cy, w, h 的方差）；
- **σ_a**：对中心轨迹做二次拟合，取加速度的 p90 作为过程噪声强度，`σ_a = 0.141`。
（第二差分法只作交叉验证，因为它会被量化误差压到 1.0 的地板。）

**Q4：自适应 R 的公式依据？**
A：`scale = 1 + 4(1 − IoU) + 2(1 − conf)`。直觉：IoU 低说明预测和观测差得远（可能是遮挡边缘、
快速运动、检测抖动），此时应少信观测；conf 低说明检测本身不可靠，同样放大 R。
系数 4 和 2 是相对权重（IoU 比 conf 更能反映几何质量），上界由 `scale` 自然限制在 7 左右。

**Q5：两级匹配具体怎么分？**
A：第一级同类匈牙利（class-aware），保证"杯子不会配到手机"；第二级只对"第一级没配上的
检测"和"处于 PREDICTED 态的轨迹"做跨类配对，且要求 IoU ≥ 0.8。这样既解决类别抖动
（同一物体被检测成 cup/phone 交替），又不会把两个不同的物体错配。

**Q6：max_age 为什么是 10？**
A：三个证据：遮挡 bench（k=10 保持 96.9%，k=15 掉到 0%）、max_age sweep（5 → 25 个 ID/15 次
换号；10 → 15 个 ID/5 次；20 → 13 个 ID 但顶替升到 2 次）、以及 10 帧 = 333 ms 的物理直觉
（桌面场景中一个物体被手挡住通常不超过 0.3 s）。取 10 是"保持率"和"ID 纯净度"的折中。

**Q7：为什么遮挡 15 帧就 0%？**
A：max_age=10，超过 10 帧轨迹被删，物体再现时只能新建 ID。这不是 bug，是设计取舍——
如果为了扛 15 帧把 max_age 提到 15，sweep 显示 ID 数会继续降但顶替次数上升（两个目标
互相抢 ID 的风险变大）。

**Q8：lag 1.239 px 是什么？怎么测的？**
A：平滑滞后：把追踪框中心与检测框中心对齐后，追踪结果相对检测的相位延迟（像素）。
卡尔曼本质是低通，抑制抖动必然带来滞后，1.24 px 在 1280×720 上约 0.1% 画幅，可接受。

**Q9：静止目标为什么不如"原地保持"？**
A：卡尔曼把检测框的随机抖动当成速度，于是有小幅漂移；而"原地保持"直接冻结位置，反而更稳。
实测 v=0 时 4.73 vs 0.93 px。改进：加"静止判据"（N 帧内位移 < 阈值 → 速度清零、Q 调小）。
我把它写进报告的局限里，而不是藏起来。

**Q10：手机检出率 36% 对追踪的影响？**
A：手机漏检多 → 轨迹频繁断、ID 数上升、遮挡保持率被拉低。数据上 2541 帧里手机只检出 911 帧
（35.9%）。这是检测端的问题（训练集里手机都是平放），不是追踪算法的问题；追踪层的
`max_age=10` 已经能顶住 0.33 s 的漏检。

**Q11：双胞胎 6 对是怎么剩下的？**
A：主要是类别抖动 + 短暂遮挡后新建轨迹。已用"同类 IoU>0.6 抑制新建"和"跨类救援"降到 6
（基线 25），但无法归零，因为有些帧里两个物体确实重叠、检测框也重叠。

**Q12：交叉只有 1.2 s，题面要 3 s，怎么办？**
A：实话实说：素材是自拍的，手机从杯子前面穿过的连续重叠只有约 1.2 s（传递过程约 2.5 s，
峰值 IoU 0.898）。这不是算法问题，是素材限制；如果用两辆小车或两个大物体对穿，重叠时间
可以拉长。我能证明的是"在这 1.2 s 里两个 ID 没有互换"。

### 6.2 数据与诚信追问

**Q13："这些数字是你跑的还是编的？"**
A：全部来自仓库脚本：`evaluate_tracking.py` → `results/compare.csv`；`occlusion_bench.py` →
`results/occlusion_bench.csv` 与 `max_age_sweep.csv`；`derive_noise.py` → `noise_params.json`；
`simulate_prediction_bench.py` → `prediction_sim.json`。视频、检测 JSON、追踪视频三者帧数
一致（2541），可以现场重跑任意一项。

**Q14："人工遮挡算不算作弊/造假？"**
A：不算，它是**受控实验**：故意遮住 k 帧，测"能不能用原 ID 接回来"，用于标定 max_age。
它和"自然断档统计"是两个独立实验，报告里分开写；自然断档那条曲线只覆盖准静止目标
（`gap/moving n=0`），我没有拿它冒充"运动目标遮挡"。

**Q15："没有真值标注，你怎么知道追踪是对的？"**
A：用"伪真值"：同一物体的检测序列在时间上连续，取中位数作为参考轨迹，再算 ID 一致性。
它的局限是"检测错了也会跟着错"，所以我又加了不依赖真值的指标（双胞胎、jitter、静止方差、
lag），多指标交叉验证。

### 6.3 承认局限的标准句式

> 「这条曲线只能说明准静止目标的情况——自然断档里没有"运动中被遮挡"的样本
> （`gap/moving n=0`），所以运动预测的收益我另做了受控仿真（v=5、k=10：4.39 vs 49.98 px）
> 和人工遮挡实验。两者不能混着说，报告里是分开的。」

### 6.4 没做过的事怎么答

「没做 ReID / 没做 IMM / 没做场景自适应 max_age。原因是 CPU 预算和本题规模：6 类桌面物体、
最多 3 个同时出现，IoU + 卡尔曼已经够用。如果目标数上到 20 个、遮挡超过 0.5 s，我会优先加
外观特征（轻量 ReID）和 IMM（匀速 + 转弯两个模型）。」

## 7. 一句话记忆锚点

- **结构**：检测 → 卡尔曼预测 → 两级匈牙利 → 自适应 R → 生命周期（max_age=10）；
- **三个数**：双胞胎 6 vs 25、ID 15 vs 17、遮挡 ≤10 帧 100%；
- **一个代价**：1.24 px 滞后；
- **两个反例**：静止目标不如 hold（4.73 vs 0.93）、交叉只有 1.2 s；
- **参数出处**：R/σ_a 来自 `derive_noise.py`，max_age 来自 sweep。
