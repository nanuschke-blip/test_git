# M1-3 时间与坐标 —— 设计逻辑 / 原理 / 知识点 / 算法

> 对应 `round1/M1/M1-3`。一句话：**不同传感器、不同频率、不同时间戳的数据，靠 TF 与时间同步
> "说到一起去"**，再用针孔模型把激光点画到图像上。

## 1. 整体数据流

```
sample_bag (rosbag2)
 ├── /scan            10 Hz, frame=laser_link, 180 线, 只含 range
 ├── /camera/image_raw 27 Hz, frame=camera_link, 640x480 rgb8
 └── /camera/camera_info  内参 K
        │
        ▼
[projection_node]
  1) 读 extrinsics.yaml（外参 xyz/rpy + 内参 fx,fy,cx,cy）——唯一真值来源
  2) StaticTransformBroadcaster 发布 map→odom→base_link→{laser_link, camera_link}
  3) ApproximateTimeSynchronizer(slop, queue) 配对 /scan 与 /camera/image_raw
  4) laser_link → base_link → camera_link → 光学系 → 针孔投影 (u,v)
  5) 画点（近红远蓝）→ 发布 /projection/debug_image + 存 projection_N.png
```

## 2. TF2 原理

### 2.1 坐标系约定（REP-103 / REP-105）

- `map`：世界固定系（全局一致，可跳变）；
- `odom`：里程计系（连续、无跳变、长期漂移）；
- `base_link`：车体（x 前、y 左、z 上）；
- `laser_link` / `camera_link`：传感器系，用 `parent + xyz + rpy` 描述。

### 2.2 变换的表示

一个刚体变换 = 旋转 R + 平移 t。TF 用**四元数**存旋转（避免万向锁、插值稳定）。
由 RPY 生成四元数（ZYX 顺序）：

```
qx = sr·cp·cy − cr·sp·sy
qy = cr·sp·cy + sr·cp·sy
qz = cr·cp·sy − sr·sp·cy
qw = cr·cp·cy + sr·sp·sy
```

### 2.3 静态 TF 与动态 TF

| | StaticTransformBroadcaster | TransformBroadcaster |
|---|---|---|
| 话题 | `/tf_static`（QoS: transient_local，后加入的节点也能收到） | `/tf` |
| 时间 | **与时间无关**，任何 stamp 都有效 | 每帧带时间戳，需要插值 |
| 用途 | 传感器安装位置（本题） | 车体运动 odom→base_link |

本题 `map→odom→base_link` 取单位变换（车不动），`base_link→laser_link`、
`base_link→camera_link` 用 yaml 数值，一次性 `sendTransform(list)` 即可。

### 2.4 `lookup_transform(target, source, time)` 的方向

**返回的是 `source` 在 `target` 系下的位姿**，即把点从 `source` 变到 `target` 的变换。
参数写反 = 得到逆变换，这是经典错误。代码里等价于：

```
T_target_source = T_target_world · T_world_source
```

### 2.5 为什么"静态 TF 与时间无关"很关键

因为静态变换对所有时间戳都成立，所以**即使 `use_sim_time` 配错，`lookup_transform` 也不会失败**，
投影照样能出图。真正会挂的是：动态 TF 的插值（时间对不上直接抛 extrapolation）、
基于 `now()` 的超时/心跳判断、RViz 的时间轴。这就是为什么本题"配错也能跑通"很容易被忽略。

## 3. 时间系统

- 每个节点有自己的 `Clock`；`use_sim_time=true` 时，`node.get_clock().now()` 跟随 `/clock` 话题；
- `ros2 bag play --clock` 才会发布 `/clock`（否则没有时间源，节点时钟仍是墙钟）；
- 消息的 `header.stamp` 是**数据产生时刻**，与节点接收时刻不同——同步必须用 header 时间戳。

实测对比（同一份 bag）：

| use_sim_time | node_clock | scan_stamp | 差值 |
|---|---|---|---|
| true | 2.794 | 2.803 | 0.009 s |
| false | 1795058736.861 | 0.997 | 1.79e9 s |

## 4. 时间同步算法

### 4.1 两种 Synchronizer

| | ExactTime | ApproximateTime |
|---|---|---|
| 条件 | 所有消息 stamp **完全相等** | stamp 之差 ≤ slop |
| 本题适用 | ❌ 一帧都配不上（两路时间戳不可能相等） | ✅ |

### 4.2 ApproximateTime 的工作方式（简化）

维护每个话题的消息队列；新消息到达时，从队列里找"时间跨度最小、且跨度 ≤ slop"的一组
候选（以最新消息为 pivot），配对成功就弹出。队列长度 `queue_size` 决定能容忍多少积压。

因为它按时间顺序推进并弹出已配对消息，**相机多出来的帧会被丢弃**（2.7 倍速率）。
所以：实际配对时间差 = 该雷达帧与"被选中相机帧"之差，通常不是全局最近的那一帧。

### 4.3 slop 的取舍（本数据实测）

| slop | 配对率 | 中位 dt | 最大 dt |
|---|---|---|---|
| 5 ms | 32% | 2.74 ms | 4.63 ms |
| 10 ms | 52% | 4.33 ms | 9.03 ms |
| 15 ms | 82% | 7.19 ms | 14.33 ms |
| 20 ms | 98% | 8.69 ms | 19.62 ms |
| ≥30 ms | 100% | 8.86 ms | 20.77 ms |

物理上限：相机 27 Hz → 半个周期 18.5 ms，加抖动 ≈ 20.8 ms。所以 **slop 一旦 ≥ 21 ms 就必然
100% 配对**；再大只是"允许更差的匹配"，不会增加配对数量。

选择 60 ms 的理由：≈3 倍最大时间差，能容忍相机偶发丢帧；又 < 一个雷达周期（100 ms），
避免配到"上一帧"的相机图像。

### 4.4 queue_size 的作用

相机 27 Hz、雷达 10 Hz，若 `queue_size` 只有 5，队列里很快被相机帧填满、早期雷达帧被挤出，
导致"启动阶段丢帧"。本题取 50（≈1.8 s 的相机数据）。

## 5. 针孔相机模型与投影

### 5.1 内参

```
K = [[fx, 0, cx],
     [0, fy, cy],
     [0, 0, 1]]
```

`fx = f / pixel_size_x`，`cx, cy` 是主点（通常≈图像中心）。

### 5.2 投影公式（光学系下）

```
u = fx · X/Z + cx
v = fy · Y/Z + cy        （Z 为深度，必须 > 0）
```

### 5.3 机体系 → 光学系

`camera_link` 遵循 REP-103：x 前、y 左、z 上；
光学系：x 右、y 下、z 前。二者差一个固定旋转：

```
R_body→opt = [[0, -1, 0],
              [0,  0,-1],
              [1,  0, 0]]
```

即 `x_opt = -y_body`（左→右镜像）、`y_opt = -z_body`（上→下）、`z_opt = x_body`（前进方向）。
用错方向（写成转置）→ 图像上下颠倒/左右镜像。

### 5.4 完整的变换链

```
P_laser (z=0)
  → P_base = R_laser · P_laser + t_laser
  → P_cam  = R_cam^T · (P_base − t_cam)
  → P_opt  = R_body→opt · P_cam
  → (u, v) = (fx·X/Z + cx, fy·Y/Z + cy)
```

行向量实现里 `v' = v @ M` 等价于 `v' = M^T v`，所以"把 base 点转到相机系"写 `@ R_cam`，
而"把机体点转到光学系"要写 `@ R_body→opt.T`——这是本次实现里唯一一处真正写错过的符号。

### 5.5 为什么点落在图像中心偏下

相机 z=0.30，激光平面 z=0.20，激光点在相机下方 0.10 m：
`v = fy·(0.10)/X + cy > cy`，X≈2.4~4.3 m → 偏移 12~21 px，所以点带在中心偏下一条水平线上。
现场换外参（如 laser-z 0.45 / camera-z 0.75）后这条线的位置会变，正好验证"读 yaml 而非写死"。

## 6. 颜色映射

按距离线性映射到红→蓝：

```
t = (d − d_min) / max(d_max − d_min, 0.5)
color = (255·(1−t), 40, 255·t)
```

用**本帧**的 d_min/d_max 归一化（而不是固定 5 m），否则近距离场景会全挤在紫色区间。

## 7. 现场"换外参"为什么能验证真伪

真值只有 `extrinsics.yaml` 一份。若代码里写死 `0.15/0.20/500`，现场用
`--laser-z 0.45 --camera-z 0.75 --fx 420` 重生成数据后，投影会落到画面外或明显偏移；
读 yaml 的实现只改文件、不改代码就能对上。

## 8. 十个坑

1. 用 `TimeSynchronizer` 精确同步 → 一帧都配不上；
2. `queue_size` 太小 → 启动阶段丢帧；
3. `lookup_transform(target, source)` 参数写反 → 得到逆变换；
4. 忘记 `bag play --clock` 或少 `use_sim_time:=true` → 时间基准不一致；
5. 把 `camera_link` 当光学系直接投影 → 上下颠倒/左右镜像；
6. 代码里写死外参/内参 → 现场换参数当场错；
7. `Z <= 0` 的点没剔除 → 出现镜像的"鬼点"；
8. `range` 里的 `inf`（无回波）没过滤 → numpy 里 inf/nan 污染整批点；
9. 用 `np.arange(len(ranges))*angle_increment` 时忘了加 `angle_min`；
10. 颜色用固定 5 m 归一化 → 近距场景颜色区分不出来。

## 9. 性能

60 帧雷达 / 162 帧相机（5 s 数据）：单个节点处理全部帧 < 1 s（每帧 180 个点、640×480 图像），
`bag play` 实时回放不丢帧；瓶颈在图像 memcpy 与 PNG 写盘（每张约 0.5 MB，只存前 3 张）。

## 10. 可扩展

- 加畸变校正（`cv2.undistort`）与投影后的 ROI 裁剪；
- 用 `tf2_ros.Buffer.lookup_transform` 做时间插值，对比"直接读 yaml"的差异；
- 把点云改成 `PointCloud2` 并行投影（多雷达融合）；
- 用 `image_transport` 压缩传输，降低带宽；
- 用 `message_filters::Cache` 做"每个雷达帧找最近相机帧"（复杂度 O(1)），对比 ApproximateTime 的丢帧行为；
- 在图像上叠加距离直方图/最近障碍物框，为后续 M2 的检测做前置。
